# Domain docs

## Before exploring

- Read `GLOSSARY.md` for domain vocabulary.
- Read relevant decisions in `docs/adr/` before changing that area.

If either reference is absent, proceed without creating one unless domain terminology or a decision needs recording.

## Layout

This is a single-context repo: root `GLOSSARY.md` and system decisions in `docs/adr/`.

## Vocabulary

Use glossary terms in issue titles, refactor proposals, hypotheses, and test names. If a needed concept is undefined, note the gap for domain modeling.

## ADR conflicts

Surface any proposal that contradicts an accepted ADR and explain why reopening it is warranted.
